# Задание 9. Имитационная модель обслуживания заявок (Теория массового обслуживания)

Разработка упрощенной дискретно-событийной модели системы массового обслуживания (СМО). В систему поступают заявки, которые проходят обработку в одну стадию. Очередь обслуживают два типа рабочих: основные и резервные. Резервный рабочий подключается к работе только тогда, когда длина очереди превышает критический порог. Модель должна оценивать показатели загруженности и среднюю длину очереди.

## Архитектура проекта

### 1. Header-only часть
* **Заявка (Request):** идентификатор, время прихода в систему, время начала и окончания обработки.
* **Рабочий (Worker):** идентификатор, тип (основной / резервный), статус (свободен / занят), суммарное время работы.
* **Событие (Event):** время наступления, тип события (приход заявки / завершение обработки конкретным рабочим).
* **Итоговый отчет (SimulationReport):** среднее время ожидания заявки в очереди, средняя длина очереди, коэффициенты загрузки рабочих каждого типа.

### 2. Статическая часть
* **Календарь событий (FEC — Future Event List):** список будущих событий, отсортированный по времени их наступления.
* **Очередь заявок (CEC — Current Event List):** список заявок, ожидающих освобождения рабочих.
* Генератор случайных чисел по экспоненциальному закону на основе заданного среднего времени (интенсивности).
* Имитационный цикл: извлечение ближайшего события из FEC, продвижение модельного времени, изменение состояний рабочих и очередей.
* **Правило резерва:** резервный рабочий берет заявку из очереди только в том случае, если текущий размер очереди строго больше заданного порога $K$.
* **Ограничение:** во время имитации запрещены любые выводы в консоль и работу с диском.

### 3. Динамическая часть (DLL)
* Импорт конфигурации модели из текстового файла (параметры: среднее время между заявками, среднее время обработки, количество основных и резервных рабочих, порог включения резерва $K$, общее время моделирования).
* Экспорт текстового лога моделирования (пошаговое изменение списков событий FEC и очереди CEC) и итогового аналитического отчета.

### 4. Демо-приложение
Связывает модули между собой:
* Загрузка параметров СМО из файла конфигурации через DLL.
* Запуск имитационного моделирования в памяти через статику.
* Вывод на экран краткой сводки: средняя длина очереди и вердикт — достаточно ли рабочих, чтобы очередь не превышала 2 заявок.
* Сохранение пошагового лога событий (`simulation.log`) через DLL.

---

## Тестирование

### Тесты статики
* Идеальный случай: интенсивность прихода заявок намного ниже скорости работы основных сотрудников (резервные рабочие всегда свободны, очередь равна нулю).
* Случай перегрузки: интенсивность прихода выше возможностей всей системы (очередь непрерывно растет, резервные рабочие загружены на 100%).
* Проверка генератора: среднее значение сгенерированных случайных величин на большой выборке (10 000 вызовов) совпадает с заданным математическим параметром.
* Корректность сортировки: проверка, что календарь событий (FEC) всегда упорядочен строго по возрастанию времени.
